## 1\. The big picture

**What we are building.** A small 3-joint robot arm, designed in Fusion 360, plus a **neural network that plans the arm's motion** from a start pose to a goal pose while avoiding obstacles. We then show the arm moving in a simulator and compare our neural planner against a classical planner.

```
        FUSION 360                      PYTHON (our own code)                    SIMULATION
 ┌────────────────────┐        ┌─────────────────────────────────────┐     ┌──────────────────────┐
 │ CAD model of arm   │        │ kinematics.py  (math of the arm)    │     │ PyBullet (physics    │
 │  - links, joints   │ STL    │ collision.py   (is a pose safe?)    │     │   viewer, Day 3)     │
 │  - dimensions      ├───────►│ rrt\_connect.py (classical planner,  │────►│                      │
 │  - joint limits    │ + URDF │                the "teacher")       │     │ RViz via ROS 2       │
 └────────────────────┘        │ gen\_dataset.py (teacher makes data) │     │   (final demo, Day 6)│
                               │ train.py       (network learns)     │     └──────────────────────┘
                               │ planner.py     (network plans)      │
                               └─────────────────────────────────────┘
```

**The idea of the ML part, in plain words.** A classical planner (RRT-Connect) finds safe paths by random trial and error. It works but is slow and random. We let that planner solve thousands of random problems, record its answers, and train a neural network to imitate it. After training, the network can say "from where I am now, with this goal and these obstacles, the next small step should be *this*". Repeating that gives a full path. If the network ever fails, we fall back to the classical planner. At the end we measure success rate, speed and smoothness of both.

**Why this design is safe for one week.**

* The dataset is generated by our own code, so there is nothing to download and no waiting for data.
* The collision checker is simple math (links as thick lines, obstacles as spheres), so it is very fast. Data generation takes minutes, not days.
* Fusion is used for what it is good at (the 3D model), and the ML work does not depend on Fusion being finished. Two parts of the team can work in parallel.
* Everything has a fallback (Section 15).

## 6\. Day 1: kinematics (the math) and Fusion basics

### 6.1 Understand forward and inverse kinematics

Our arm works in one **vertical plane** that rotates around the Z axis by `q1`.

* `a2 = q2` is the absolute angle of the upper arm above horizontal.
* `a3 = q2 + q3` is the absolute angle of the forearm above horizontal.
* In the vertical plane: horizontal distance `r = L1·cos(a2) + L2·cos(a3)`, height `z = H + L1·sin(a2) + L2·sin(a3)`.
* Then rotate by `q1`: `x = r·cos(q1)`, `y = r·sin(q1)`.

That is **FK**. For **IK** we go backwards. `q1 = atan2(y, x)`. For `q2, q3` we use the law of cosines on the triangle formed by the shoulder, elbow and tip; this gives `cos(q3) = D` and two solutions: **elbow up** (`q3 < 0`) and **elbow down** (`q3 > 0`). IK returns `None` when the target is out of reach or violates joint limits.

Why we need both:

* FK is used everywhere: collision checking and drawing.
* IK is used to turn a goal "go to (x, y, z)" into joint angles for the planner, and to verify FK.

### 6.2 Put these files in the project

`config.py` holds all constants. **Never hard-code these numbers elsewhere.**

```python
import numpy as np

# ---- Arm geometry (metres). MUST match the Fusion 360 model ----
H  = 0.10    # height of shoulder axis above the floor
L1 = 0.30    # shoulder -> elbow
L2 = 0.25    # elbow -> tool tip

# ---- Joint limits (radians). MUST match Fusion joint limits and URDF ----
Q\_MIN = np.array(\[-2.8, -0.5, -2.4])
Q\_MAX = np.array(\[ 2.8,  2.0,  2.4])

# ---- Collision settings ----
LINK\_RADIUS = 0.03   # every link is treated as a "fat line" of this radius
FLOOR       = 0.02   # elbow / tool must stay above this height
MAX\_OBS     = 3      # up to 3 spherical obstacles

# ---- Planner settings ----
STEP = 0.1           # rad. spacing between waypoints in the dataset
```

`kinematics.py`:

```python
import numpy as np
from config import \*

def fk\_points(q):
    """Positions of shoulder, elbow and tool tip (metres) for joint angles q."""
    q1, q2, q3 = q
    c1, s1 = np.cos(q1), np.sin(q1)
    a2, a3 = q2, q2 + q3                      # absolute angle of each link
    sh  = np.array(\[0.0, 0.0, H])
    el  = sh + L1 \* np.array(\[np.cos(a2) \* c1, np.cos(a2) \* s1, np.sin(a2)])
    tip = el + L2 \* np.array(\[np.cos(a3) \* c1, np.cos(a3) \* s1, np.sin(a3)])
    return sh, el, tip

def fk(q):
    return fk\_points(q)\[2]

def ik(target, elbow\_up=True):
    """Joint angles that put the tip at target (x,y,z). Returns None if impossible."""
    x, y, z = target
    q1 = np.arctan2(y, x)
    r  = np.hypot(x, y)
    zz = z - H
    D  = (r\*r + zz\*zz - L1\*L1 - L2\*L2) / (2\*L1\*L2)
    if abs(D) > 1.0:
        return None                            # out of reach
    s  = np.sqrt(1.0 - D\*D)
    q3 = -np.arctan2(s, D) if elbow\_up else np.arctan2(s, D)
    q2 = np.arctan2(zz, r) - np.arctan2(L2\*np.sin(q3), L1 + L2\*np.cos(q3))
    q  = np.array(\[q1, q2, q3])
    if np.any(q < Q\_MIN) or np.any(q > Q\_MAX):
        return None                            # violates joint limits
    return q
```

`test\_kinematics.py` checks FK and IK against each other on 1000 random poses:

```python
import numpy as np
from config import \*
from kinematics import fk, ik

rng = np.random.default\_rng(0)
ok = 0
for \_ in range(1000):
    q = rng.uniform(Q\_MIN, Q\_MAX)
    target = fk(q)
    for elbow\_up in (True, False):
        qi = ik(target, elbow\_up)
        if qi is not None:
            assert np.linalg.norm(fk(qi) - target) < 1e-9, "IK/FK mismatch!"
            ok += 1
print("zero pose tip:", fk(\[0, 0, 0]), "(expect \[0.55, 0, 0.10])")
print("FK/IK round-trips passed:", ok)
```

Run:

```bash
python test\_kinematics.py
```

**Checkpoint 1a:** it prints `zero pose tip: \[0.55 0. 0.1]` and a number of round-trips passed, with no assertion error.

## 7\. Day 2: model the arm in Fusion 360 (Role A leads; everyone helps)

> Menu names can shift slightly between Fusion versions. If a button is not where described, use the search box (the magnifier, or press `S` to open the command search) and type the command name.

### 7.1 One-time setup (do this first!)

1. **Make Z the up direction.** Click your profile picture (top right) → **Preferences** → **General** → *Default modeling orientation* → **Z up**. Fusion's default is Y-up, which would break our axes. Restart the design after changing it.
2. **Units in millimetres.** In the browser panel (left), open *Document Settings* → *Units* → **Millimeter**.
3. Save the design as `arm3dof`.

### 7.2 Dimensions to model (all in the zero pose, arm stretched along +X)

We keep shapes very simple: cylinders and "slot" shapes (a rectangle with round ends).

|Component|Shape|Dimensions (mm)|
|-|-|-|
|`base`|Cylinder standing on the floor|Diameter 140, height 40 (z from 0 to 40)|
|`turret`|Cylinder (the rotating column) + shoulder hub|Column diameter 80, z from 40 to 100. Hub: cylinder along the Y axis, diameter 60, length 80 (y from -40 to +40), centred at x=0, z=100|
|`upper\_arm`|Slot shape in the XZ plane|Slot centres at (x=0, z=100) and (x=300, z=100); width 40; thickness 40 (y from -20 to +20)|
|`forearm`|Slot shape in the XZ plane|Slot centres at (x=300, z=100) and (x=550, z=100); width 30; thickness 30 (y from +20 to +50)|

The forearm is shifted sideways (in Y) so it does not collide with the upper arm at the elbow; this has no effect on the maths, because the joint axis is still along Y through (x=300, z=100).

### 7.3 Step by step

**Create the components.** In the browser, right-click the top-level design name → **New Component**. Name it `base`. Repeat for `turret`, `upper\_arm`, `forearm`. (Tip: before sketching, make sure the component you want is active: it has a filled dot next to its name. Anything you draw goes into the active component.)

**Base.**

1. Activate `base`. Create Sketch on the **XY plane** (the floor).
2. Circle command (`C`): centre on the origin, diameter 140. Finish Sketch.
3. Extrude (`E`): pick the circle, distance 40 mm, direction up.

**Turret column.**

1. Activate `turret`. Sketch on the **top face of the base** (z = 40). Circle diameter 80 at the origin.
2. Extrude 60 mm upward (so the column ends at z = 100).

**Shoulder hub.**

1. Still in `turret`: Sketch on the **XZ plane** (this is the vertical plane through the origin). Draw a circle of diameter 60 centred at (0, 100), i.e. x = 0, height 100 mm. (If the sketch shows z pointing down, put the centre at the height that appears 100 mm above the floor.)
2. Extrude with **Symmetric** direction, distance 80 mm (so it goes 40 mm to each side).

**Upper arm.**

1. Activate `upper\_arm`. Sketch on the **XZ plane**.
2. Use **Create → Slot → Center to Center Slot**. Click centre points at (0, 100) and (300, 100); set slot width 40.
3. Extrude with **Symmetric**, distance 40 mm.

**Forearm.**

1. Activate `forearm`. Sketch on the XZ plane. Slot with centres (300, 100) and (550, 100), width 30.
2. Extrude: in the Extrude dialog set *Start* to **Offset** = 20 mm, distance = 30 mm. If the solid goes to the wrong side (negative Y), flip the direction. It must end up at y from +20 to +50.

Optional extras if time allows: a gripper stub, rounded edges (Modify → Fillet), colours (right-click body → Appearance).

### 7.4 Add the joints (this lets you test the motion inside Fusion)

1. Right-click `base` → **Ground**. A grounded part cannot move.
2. **Assemble → Joint.**

   * **Joint 1**: Component 1 = `turret`, Component 2 = `base`. Click the circular edge of the turret's bottom face (a centre-point snap appears). Motion type **Revolute**, axis **Z**. Under *Limits*, enable and set min -160° (≈ -2.8 rad) and max +160°.
   * **Joint 2**: `upper\_arm` to `turret`. Snap to the **centre of the hub's circular end face**. Revolute, axis **Y**. Limits: min -29° and max +115°. (Which sign is "up" depends on the axis direction; test it as below, and if positive lifts the arm *down*, swap the limits' signs.)
   * **Joint 3**: `forearm` to `upper\_arm`. Snap to the **centre of the round end of the upper arm** at x = 300. Revolute, axis **Y**. Limits ±137°.
3. **Test**: drag the arm with the mouse; it must rotate only about the three joints and stop at the limits.
4. **Return to the zero pose** (arm straight along +X) before exporting: right-click each joint in the browser and edit its angle to 0 (**Edit Joint Angle**; if you do not see it, use Ctrl+Z or drag the Timeline marker back to before the test).

### 7.5 Measure, then check against the spec

Use **Inspect → Measure** to verify:

* Shoulder axis height = 100 mm above the floor.
* Distance between shoulder axis and elbow axis = 300 mm.
* Distance between elbow axis and the end of the forearm's round end centre = 250 mm.

Also assign a material (right-click the component → Physical Material → Aluminium) and read each link's mass via **Inspect → Properties** (select the component). **Write the masses down**; you need them for the torque calculation on Day 7.

**Checkpoint 2:** Fusion assembly moves with 3 limited joints; measurements match the spec; zero pose restored; link masses noted. Save, and commit the `.f3d` file (File → Export → Fusion Archive) to Git.

## 8\. Day 3: Fusion to URDF to PyBullet, plus collision checking

### 8.1 Export the STL meshes from Fusion (Role A)

For each of the four components, with the arm in the **zero pose**:

1. Right-click the component in the browser → **Save As Mesh**.
2. Format **STL (Binary)**, Unit **Millimeter**, Refinement **Medium**.
3. Save as `meshes/base.stl`, `meshes/turret.stl`, `meshes/upper\_arm.stl`, `meshes/forearm.stl` (exact names).

> \*\*Why the zero pose matters:\*\* the STL stores each part's coordinates in the world frame at the moment of export. In the URDF each link has its own frame sitting at its joint, so we shift the picture back by the joint's position. That is the `<origin>` line in each `<visual>` block. Zero pose makes this offset a simple known number.

### 8.2 The URDF file (Role C)

Save as `urdf/arm3dof.urdf`:

```xml
<?xml version="1.0"?>
<robot name="arm3dof">
  <material name="grey"><color rgba="0.6 0.6 0.65 1"/></material>
  <material name="blue"><color rgba="0.2 0.4 0.9 1"/></material>
  <material name="orange"><color rgba="0.95 0.5 0.1 1"/></material>
  <material name="green"><color rgba="0.2 0.7 0.3 1"/></material>

  <!-- All STL meshes are exported from Fusion in millimetres, in the ZERO POSE
       (arm stretched along +X). scale=0.001 converts mm -> m.
       Each link's visual origin = minus the world position of that link's joint. -->

  <link name="base\_link">
    <visual>
      <geometry><mesh filename="meshes/base.stl" scale="0.001 0.001 0.001"/></geometry>
      <material name="grey"/>
    </visual>
  </link>

  <link name="turret">
    <visual>
      <geometry><mesh filename="meshes/turret.stl" scale="0.001 0.001 0.001"/></geometry>
      <material name="blue"/>
    </visual>
  </link>

  <link name="upper\_arm">
    <visual>
      <origin xyz="0 0 -0.10" rpy="0 0 0"/>
      <geometry><mesh filename="meshes/upper\_arm.stl" scale="0.001 0.001 0.001"/></geometry>
      <material name="orange"/>
    </visual>
  </link>

  <link name="forearm">
    <visual>
      <origin xyz="-0.30 0 -0.10" rpy="0 0 0"/>
      <geometry><mesh filename="meshes/forearm.stl" scale="0.001 0.001 0.001"/></geometry>
      <material name="green"/>
    </visual>
  </link>

  <link name="tool"/>

  <joint name="joint1" type="revolute">          <!-- base yaw, rotates about Z -->
    <parent link="base\_link"/><child link="turret"/>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <axis xyz="0 0 1"/>
    <limit lower="-2.8" upper="2.8" effort="20" velocity="2.0"/>
  </joint>

  <joint name="joint2" type="revolute">          <!-- shoulder pitch; -Y axis so +angle lifts the arm -->
    <parent link="turret"/><child link="upper\_arm"/>
    <origin xyz="0 0 0.10" rpy="0 0 0"/>
    <axis xyz="0 -1 0"/>
    <limit lower="-0.5" upper="2.0" effort="20" velocity="2.0"/>
  </joint>

  <joint name="joint3" type="revolute">          <!-- elbow pitch -->
    <parent link="upper\_arm"/><child link="forearm"/>
    <origin xyz="0.30 0 0" rpy="0 0 0"/>
    <axis xyz="0 -1 0"/>
    <limit lower="-2.4" upper="2.4" effort="10" velocity="2.0"/>
  </joint>

  <joint name="tool\_fixed" type="fixed">         <!-- tool tip = end of forearm -->
    <parent link="forearm"/><child link="tool"/>
    <origin xyz="0.25 0 0" rpy="0 0 0"/>
  </joint>
</robot>
```

How to read it:

* Each `<link>` is a part and says which STL to draw. `scale="0.001 0.001 0.001"` converts the STL from mm to metres.
* Each `<joint>` says how a **child** link connects to its **parent**: `origin` = where the joint is relative to the parent frame, `axis` = what it rotates around, `limit` = allowed range.
* The visual offsets (`xyz="0 0 -0.10"` for the upper arm and `xyz="-0.30 0 -0.10"` for the forearm) are minus the joint positions in the zero pose: the upper arm's frame is at world (0, 0, 0.10), the forearm's at (0.30, 0, 0.10).
* The axis `0 -1 0` is deliberate: rotating about +Y would tilt the arm *down* for positive angles; the minus sign makes **positive = up**, matching our FK.
* `tool` is an empty link at the forearm's end that marks the tool tip so we can read its position.
* We omit collision shapes and masses on purpose: our own `collision.py` handles collision checking, and RViz/PyBullet viewing do not need them.

If you want to start before Fusion's STLs exist, replace each `<mesh .../>` by a simple `<cylinder radius="0.02" length="0.30"/>` placeholder (it will look wrong but the joints will work).

### 8.3 The PyBullet viewer (Role C)

**PyBullet** is a Python physics engine that can load a URDF and show it in a window. We use it purely as a viewer and as an independent check of our maths: set the joint angles, ask PyBullet where the tool is, and compare with our own `fk()`.

`sim\_pybullet.py`:

```python
import argparse, time
import numpy as np
import pybullet as p
import pybullet\_data
from config import \*
from kinematics import fk
from problem import random\_problem
from trajectory import to\_trajectory, DT

JOINTS, TOOL\_LINK = \[0, 1, 2], 3          # PyBullet numbers joints in URDF order: joint1=0 ... tool\_fixed=3

def setup():
    p.connect(p.GUI)
```

### 8.4 Collision checking and random problems (Role B)

The planner needs a fast answer to: *"Is this arm pose safe?"* We use a simple, fast method: treat each link as a **line segment with a thickness** (`LINK\_RADIUS` = 3 cm) and each obstacle as a **sphere**. A pose collides if a segment gets closer to a sphere's centre than (sphere radius + thickness), or if the elbow or tip is nearly on the floor.

Why not use PyBullet or Fusion for this? Because we will check millions of poses when generating data; this simple maths takes microseconds per check and gives the same practical answer. (PyBullet remains the visual check.)

`collision.py`:

```python
import numpy as np
from config import \*
from kinematics import fk\_points

def seg\_point\_dist(a, b, p):
    ab = b - a
    t = np.clip(np.dot(p - a, ab) / np.dot(ab, ab), 0.0, 1.0)
    return np.linalg.norm(p - (a + t \* ab))

def in\_collision(q, obs):
    """obs: array (MAX\_OBS, 4) rows = x, y, z, radius (radius 0 = unused slot)."""
    sh, el, tip = fk\_points(q)
    if el\[2] < FLOOR or tip\[2] < FLOOR:
        return True
    for x, y, z, r in obs:
        if r <= 0:
            continue
        c = np.array(\[x, y, z])
        if seg\_point\_dist(sh, el, c) < r + LINK\_RADIUS: return True
        if seg\_point\_dist(el, tip, c) < r + LINK\_RADIUS: return True
    return False

def edge\_free(qa, qb, obs, res=0.05):
    """True if the straight joint-space line qa->qb is collision-free."""
    n = max(2, int(np.linalg.norm(qb - qa) / res) + 1)
    for t in np.linspace(0.0, 1.0, n):
        if in\_collision(qa + (qb - qa) \* t, obs):
            return False
    return True
```

`edge\_free` checks the straight line between two poses by testing many intermediate poses (every 0.05 rad), because a path can collide *between* two safe poses.

`problem.py` creates random test problems: random obstacles, random safe start and goal poses. With `hard=True` we keep only problems where going straight is blocked, so the planner must work to find a way:

```python
import numpy as np
from config import \*
from collision import in\_collision, edge\_free

def random\_obstacles(rng):
    n = rng.integers(1, MAX\_OBS + 1)
    obs = np.zeros((MAX\_OBS, 4))
    for i in range(n):
        dist = rng.uniform(0.15, 0.45)
        ang  = rng.uniform(-np.pi, np.pi)
        obs\[i] = \[dist\*np.cos(ang), dist\*np.sin(ang), rng.uniform(0.10, 0.45), rng.uniform(0.04, 0.08)]
    return obs

def random\_free\_q(rng, obs):
    while True:
        q = rng.uniform(Q\_MIN, Q\_MAX)
        if not in\_collision(q, obs):
            return q

def random\_problem(rng, hard=True):
    """Random (start, goal, obstacles). hard=True keeps only problems where the
    straight line in joint space is blocked, so planning is really needed."""
    for \_ in range(200):
        obs = random\_obstacles(rng)
        qs = random\_free\_q(rng, obs)
        qg = random\_free\_q(rng, obs)
        if np.linalg.norm(qg - qs) < 1.0:
            continue
        if hard and edge\_free(qs, qg, obs):
            continue
        return qs, qg, obs
    return qs, qg, obs
```

## 9\. Day 4: the classical planner (RRT-Connect) and the dataset

### 9.1 How RRT-Connect works

1. Keep **two trees** of safe poses: one rooted at the start, one at the goal.
2. Pick a random pose. Move the start tree one small step toward it (if the step is safe, add the new point).
3. Now try to move the goal tree, step after step, toward the point the start tree just added.
4. If the trees touch, trace back through both trees: that is your path.
5. Otherwise swap the roles of the two trees and repeat.

The raw path is jagged, so we run **shortcutting** (skip unnecessary wiggles) and then **densify** (insert points so neighbouring poses are at most 0.1 rad apart). Dense, evenly spaced waypoints are what the neural network will learn to imitate.

`rrt\_connect.py`:

```python
import numpy as np
from config import \*
from collision import edge\_free

def \_extend(T, P, q\_target, obs, step):
    d\_all = np.linalg.norm(np.array(T) - q\_target, axis=1)
    i = int(np.argmin(d\_all))
    d = d\_all\[i]
    if d < 1e-9:
        return "reached", i
    if d <= step:
        q\_new, status = q\_target.copy(), "reached"
    else:
        q\_new, status = T\[i] + (q\_target - T\[i]) \* step / d, "advanced"
    if not edge\_free(T\[i], q\_new, obs):
        return "trapped", i
    T.append(q\_new); P.append(i)
    return status, len(T) - 1

def \_trace(T, P, i):
    out = \[]
    while i != -1:
        out.append(T\[i]); i = P\[i]
    return out\[::-1]

def rrt\_connect(qs, qg, obs, rng, max\_iter=3000, step=0.25):
    """Returns a list of joint vectors from qs to qg, or None."""
    Ta, Pa = \[np.array(qs, float)], \[-1]
    Tb, Pb = \[np.array(qg, float)], \[-1]
    swapped = False
    for \_ in range(max\_iter):
        q\_rand = rng.uniform(Q\_MIN, Q\_MAX)
        st, ia = \_extend(Ta, Pa, q\_rand, obs, step)
        if st != "trapped":
            q\_new = Ta\[ia]
            while True:
                st2, ib = \_extend(Tb, Pb, q\_new, obs, step)
                if st2 != "advanced":
                    break
            if st2 == "reached":
                pa, pb = \_trace(Ta, Pa, ia), \_trace(Tb, Pb, ib)
                if swapped:
                    pa, pb = pb, pa
                return pa + pb\[::-1]\[1:]
        Ta, Tb = Tb, Ta
        Pa, Pb = Pb, Pa
        swapped = not swapped
    return None

def shortcut(path, obs, rng, iters=100):
    path = \[p.copy() for p in path]
    for \_ in range(iters):
        if len(path) < 3:
            break
        i, j = sorted(rng.integers(0, len(path), 2))
        if j - i < 2:
            continue
        if edge\_free(path\[i], path\[j], obs):
            path = path\[:i + 1] + path\[j:]
    return path

def densify(path, step=STEP):
    """Insert points so neighbours are at most `step` rad apart."""
    out = \[np.array(path\[0], float)]
    for a, b in zip(path\[:-1], path\[1:]):
        n = max(1, int(np.ceil(np.linalg.norm(b - a) / step)))
        for k in range(1, n + 1):
            out.append(a + (b - a) \* k / n)
    return np.array(out)
```

### 9.2 How the dataset is obtained (no download needed)

There is no ready-made dataset for *our* arm, and none is needed. We generate it:

1. Create a random problem (start, goal, obstacles).
2. Solve it with RRT-Connect (the **teacher**), shortcut and densify.
3. For every consecutive pair of waypoints along the path, make one training example:

   * **Input** (21 numbers): current pose, goal pose, the difference, and the obstacles.
   * **Output** (3 numbers): the step to the next waypoint (divided by `STEP` so numbers are around 1).

One solved problem gives about 40 examples; 5000 solved problems give about 200,000 examples. In a test run during writing, one CPU core produced about 8 problems per second, so 5000 problems take about 10 minutes on one core, and less with more cores.

`features.py` turns a situation into the 21 numbers (scaled to be around -1...1, which makes learning easier):

```python
import numpy as np
from config import \*

IN\_DIM = 9 + 4 \* MAX\_OBS                      # = 21 numbers into the network
OBS\_SCALE = np.array(\[2, 2, 2, 10] \* MAX\_OBS, dtype=np.float32)

def encode(q, goal, obs):
    """Turn (current joints, goal joints, obstacles) into one normalised vector."""
    q = np.asarray(q, np.float32); goal = np.asarray(goal, np.float32)
    obs = np.asarray(obs, np.float32).flatten() \* OBS\_SCALE
    return np.concatenate(\[q / Q\_MAX, goal / Q\_MAX, (goal - q) / Q\_MAX, obs]).astype(np.float32)
```

`gen\_dataset.py` does the generation in parallel using all CPU cores (`multiprocessing.Pool`):

### 10.3 The training script

What happens: load data, hold out 10% for validation, then for each epoch go through the training data in batches of 512; for every batch compute the **loss** (how far the predicted steps are from the teacher's steps), and let the **Adam optimizer** nudge the numbers to reduce it. ### 10.4 Using the network as a planner (with fallback)

`planner.py` has three things:

* `MLPlanner.plan`: start at the start pose. Repeat up to 150 times: ask the network for a step, take it, **check that the step is collision-free**, stop when within 0.1 rad of the goal. If a step would collide, or we run out of steps, give up (return `None`).
* `plan\_hybrid`: try the network; on failure **fall back to RRT-Connect**. This is a **hybrid planner**. It cannot be worse than RRT-Connect alone in success rate, and it often saves time.
* `plan\_rrt`: the classical baseline.

```python
import numpy as np
from config import \*
from collision import edge\_free
from rrt\_connect import rrt\_connect, shortcut, densify
from features import encode

class MLPlanner:
    """Neural planner: repeatedly asks the network for the next small step."""
    def \_\_init\_\_(self, weights="models/planner.pt"):
        import torch
        from model import build\_model
        self.torch = torch
        self.net = build\_model()
        self.net.load\_state\_dict(torch.load(weights, map\_location="cpu"))
        self.net.eval()

    def plan(self, qs, qg, obs, max\_steps=150):
        q = np.array(qs, float); qg = np.array(qg, float)
        path = \[q.copy()]
        for \_ in range(max\_steps):
            if np.linalg.norm(qg - q) < STEP:          # close enough: finish in a straight line
                if edge\_free(q, qg, obs):
                    path.append(qg.copy())
                    return np.array(path)
                return None
            with self.torch.no\_grad():
                x = self.torch.tensor(encode(q, qg, obs)).unsqueeze(0)
                dq = self.net(x)\[0].numpy().astype(float) \* STEP
            n = np.linalg.norm(dq)
            if n > STEP:
                dq \*= STEP / n
            q\_next = np.clip(q + dq, Q\_MIN, Q\_MAX)
            if not edge\_free(q, q\_next, obs):           # network suggested a collision -> give up
                return None
            q = q\_next
            path.append(q.copy())
        return None

def plan\_hybrid(ml, qs, qg, obs, rng):
    """Try the neural planner; if it fails, fall back to RRT-Connect."""
    path = ml.plan(qs, qg, obs)
    if path is not None:
        return path, "ml"
    path = rrt\_connect(qs, qg, obs, rng)
    if path is None:
        return None, "fail"
    return densify(shortcut(path, obs, rng)), "rrt\_fallback"

def plan\_rrt(qs, qg, obs, rng):
    """Classical baseline: RRT-Connect + shortcut smoothing."""
    path = rrt\_connect(qs, qg, obs, rng)
    if path is None:
        return None
    return densify(shortcut(path, obs, rng))
```

> \*\*A known weakness (mention it in your report!):\*\* an obstacle can be passed on the left or on the right. A network trained to copy both can average them and head straight into the obstacle. This is exactly the failure that the fallback handles, and it explains why the neural planner alone will not reach 100%.

### 10.5 From path to smooth timed trajectory

The path is a list of poses with no timing. A real robot needs "be at this pose at this time". `trajectory.py` assigns times (speed about 0.8 rad/s) and fits a **cubic spline** (a smooth curve through the points) that starts and ends at rest:

```python
import numpy as np
from scipy.interpolate import CubicSpline
from config import \*

DT = 0.02   # seconds between commands (50 Hz)

def to\_trajectory(path, v\_max=0.8):
    """Waypoints -> smooth, timed joint trajectory (array of joint vectors every DT seconds).
    v\_max = approximate joint-space speed in rad/s. Starts and ends at rest."""
    path = np.asarray(path, float)
    seg = np.linalg.norm(np.diff(path, axis=0), axis=1)
    keep = np.concatenate(\[\[True], seg > 1e-6])
    path = path\[keep]
    seg = np.linalg.norm(np.diff(path, axis=0), axis=1)
    t = np.concatenate(\[\[0.0], np.cumsum(seg / v\_max)])
    cs = CubicSpline(t, path, bc\_type="clamped")
    ts = np.append(np.arange(0.0, t\[-1], DT), t\[-1])
    return np.clip(cs(ts), Q\_MIN, Q\_MAX)
```

## 11\. Day 6: ROS 2 and RViz demo, and video

**What this gives you:** a "proper robotics" demo. We start three programs together: `robot\_state\_publisher` (reads our URDF and turns joint angles into link positions), **RViz** (the display), and our planner node, which plans random problems and publishes the joint angles of the trajectory.

How the pieces talk (ROS 2 vocabulary):

* A **node** is a running program.
* A **topic** is a named channel. Our node **publishes** `sensor\_msgs/JointState` messages on `/joint\_states` (the three angles) and `visualization\_msgs/MarkerArray` messages on `/markers` (spheres and the path line).
* `robot\_state\_publisher` **subscribes** to `/joint\_states` and RViz draws the result.

### 11.1 The planner node

`ros2/planner\_node.py` (a plain Python script, so no ROS package building is needed):

```python
#!/usr/bin/env python3
"""Plans random problems with the trained model and publishes the motion to RViz."""
import os, sys, time
import numpy as np
import rclpy
from rclpy.node import Node
from sensor\_msgs.msg import JointState
from visualization\_msgs.msg import Marker, MarkerArray
from geometry\_msgs.msg import Point

PROJECT = os.path.dirname(os.path.dirname(os.path.realpath(\_\_file\_\_)))
sys.path.insert(0, PROJECT); os.chdir(PROJECT)
from kinematics import fk
from problem import random\_problem
from planner import MLPlanner, plan\_hybrid
from trajectory import to\_trajectory, DT

class DemoNode(Node):
    def \_\_init\_\_(self):
        super().\_\_init\_\_("ml\_planner\_demo")
        self.js\_pub = self.create\_publisher(JointState, "/joint\_states", 10)
        self.mk\_pub = self.create\_publisher(MarkerArray, "/markers", 10)
        self.ml = MLPlanner()

    def publish\_q(self, q):
        m = JointState()
        m.header.stamp = self.get\_clock().now().to\_msg()
        m.name = \["joint1", "joint2", "joint3"]
        m.position = \[float(v) for v in q]
        self.js\_pub.publish(m)

    def sphere(self, mid, c, r, rgba):
        m = Marker(); m.header.frame\_id = "base\_link"; m.ns = "scene"; m.id = mid
        m.type = Marker.SPHERE; m.action = Marker.ADD
        m.pose.position.x, m.pose.position.y, m.pose.position.z = \[float(v) for v in c]
        m.pose.orientation.w = 1.0
        m.scale.x = m.scale.y = m.scale.z = 2.0 \* float(r)
        m.color.r, m.color.g, m.color.b, m.color.a = rgba
        return m

    def path\_marker(self, pts):
        m = Marker(); m.header.frame\_id = "base\_link"; m.ns = "scene"; m.id = 100
        m.type = Marker.LINE\_STRIP; m.action = Marker.ADD
        m.pose.orientation.w = 1.0; m.scale.x = 0.01
        m.color.r, m.color.g, m.color.b, m.color.a = 0.1, 0.3, 1.0, 1.0
        m.points = \[Point(x=float(p\[0]), y=float(p\[1]), z=float(p\[2])) for p in pts]
        return m

    def idle(self, q, markers, seconds):
        end = time.time() + seconds
        while time.time() < end and rclpy.ok():
            self.publish\_q(q); self.mk\_pub.publish(markers)
            rclpy.spin\_once(self, timeout\_sec=0.0); time.sleep(0.05)

    def episode(self, seed):
        rng = np.random.default\_rng(seed)
        qs, qg, obs = random\_problem(rng)
        clear = Marker(); clear.action = Marker.DELETEALL
        items = \[clear]
        for i, o in enumerate(obs):
            if o\[3] > 0: items.append(self.sphere(i, o\[:3], o\[3], (1.0, 0.1, 0.1, 0.8)))
        items.append(self.sphere(50, fk(qs), 0.02, (0.1, 0.4, 1.0, 1.0)))
        items.append(self.sphere(51, fk(qg), 0.02, (0.1, 0.9, 0.1, 1.0)))
        scene = MarkerArray(markers=items)
        self.idle(qs, scene, 2.0)

        path, how = plan\_hybrid(self.ml, qs, qg, obs, rng)
        self.get\_logger().info(f"episode {seed}: planner = {how}")
        if path is None:
            return
        traj = to\_trajectory(path)
        scene.markers.append(self.path\_marker(\[fk(q) for q in traj\[::5]]))
        for q in traj:
            self.publish\_q(q); self.mk\_pub.publish(scene)
            rclpy.spin\_once(self, timeout\_sec=0.0); time.sleep(DT)
        self.idle(traj\[-1], scene, 2.0)

def main():
    rclpy.init()
    node = DemoNode()
    seed = 0
    while rclpy.ok():
        node.episode(seed); seed += 1
    rclpy.shutdown()

if \_\_name\_\_ == "\_\_main\_\_":
    main()
```

### 12.3 Motor torque calculation (design part of the report)

Engineers size motors for the **worst case**, the arm fully stretched out horizontally, holding its payload, because then gravity acts at the longest distance. **Torque = force × distance.**

For the shoulder (joint 2), with link masses `m1` (upper arm), `m2` (forearm), payload `mp` and gravity `g = 9.81 m/s²`:

```
τ\_shoulder = m1·g·(L1/2) + m2·g·(L1 + L2/2) + mp·g·(L1 + L2)
τ\_elbow    = m2·g·(L2/2) + mp·g·L2
```

(`L/2` because a uniform link's weight acts at its middle.)

**Worked example** (replace with your Fusion masses): `m1 = 0.40 kg`, `m2 = 0.30 kg`, `mp = 0.20 kg`.

* `τ\_shoulder = 0.40·9.81·0.15 + 0.30·9.81·0.425 + 0.20·9.81·0.55 = 0.589 + 1.251 + 1.079 ≈ 2.92 N·m`
* `τ\_elbow = 0.30·9.81·0.125 + 0.20·9.81·0.25 = 0.368 + 0.491 ≈ 0.86 N·m`

Apply a safety factor of 2 (for acceleration, friction, motor losses): the shoulder needs about **5.8 N·m** at the joint output. A small motor has far less torque than that, so engineers add a **gearbox** with ratio *N*: output torque = motor torque × *N* × efficiency. For example, a motor giving 0.5 N·m through a 15:1 gearbox at 85% efficiency gives about 6.4 N·m. Put this table (required torque, chosen gear ratio, chosen motor class) in the report; you do not need to build the hardware.

## 13\. How Fusion, code and simulation fit together

This is the "integration" part in one place.

```
 Fusion 360 ──(Save As Mesh, zero pose)──► meshes/\*.stl ─┐
     │                                                    ├─► urdf/arm3dof.urdf ─► PyBullet / RViz show the arm
     └─(dimensions and limits typed once)─► config.py ────┘                │
                                         (H, L1, L2, Q\_MIN, Q\_MAX)          │
                                              │                              │
   kinematics.py ◄── same numbers ────────────┘      joint angles from the planner move the URDF joints
   collision.py  ◄── same numbers
   planner.py (neural + RRT) ──► joint trajectory ───────────────────────────┘
```

**The three things that must agree** (check them after every Fusion change):

|Quantity|`config.py`|URDF|Fusion|
|-|-|-|-|
|Shoulder height|`H = 0.10`|joint2 `origin z = 0.10`|hub centre at z = 100 mm|
|Upper arm length|`L1 = 0.30`|joint3 `origin x = 0.30`|300 mm between axes|
|Forearm length|`L2 = 0.25`|`tool\_fixed origin x = 0.25`|250 mm to tip|
|Joint ranges|`Q\_MIN`, `Q\_MAX`|`<limit lower upper>`|joint limits|
|Link thickness|`LINK\_RADIUS = 0.03`|n/a|link width 40/30 mm (half-width below 30 mm)|

**If you change the arm in Fusion** (for example, longer forearm): update the Fusion dimensions, the three config values, the URDF offsets, re-export the STLs, then **regenerate the dataset and retrain**, because the old dataset describes the old arm. `--fkcheck` tells you whether everything is consistent again.

**The key point for the report:** the neural planner only knows the arm through the numbers in `config.py`, so the Fusion model, the URDF and the planner all describe the same robot because they share these numbers, verified by the FK check within 1 mm.

## 14\. Troubleshooting

|Problem|Likely cause|Fix|
|-|-|-|
|`ModuleNotFoundError: config`|Running from a different folder|`cd arm\_ml`|
|`pip install pybullet` fails|No compiler / unsupported Python|Python 3.10/3.11, or conda-forge|
|Dataset generation very slow|Pure-Python collision checks|Run overnight/in background, reduce to 3000 problems, or lower `max\_iter` in `rrt\_connect`|

|Training loss does not fall|Wrong/empty data|Print `X.shape`; regenerate the dataset|
|Network never succeeds|Averaging of multimodal paths; too little data|More data, longer training; rely on the hybrid planner; explain in the report|
|RViz shows no robot|Fixed frame wrong or description topic wrong|Fixed frame = `base\_link`; RobotModel description topic = `/robot\_description`; check `ros2 topic list`|

|Arm moves wrongly in RViz but right in PyBullet|Joint names mismatch|Names in the node (`joint1..3`) must equal the URDF|
